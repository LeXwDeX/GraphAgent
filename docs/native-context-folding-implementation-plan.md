## 1. 固定范围与实施顺序

最终交付必须是默认开启的内置严格重复去噪：只折叠有完整后续替代副本的旧 read/grep/glob 正文。唯一结果、受保护内容和原始历史保持不变；全文压缩继续使用原有流程。

建议在同一功能分支上按以下步骤形成可审查的小提交，聚合为一项完整功能交付。在配置兼容、两条会话路径和保护回归完成之前，不单独发布已经默认开启的半成品。

| 步骤 | 工作                         | 前置依赖 | 主要责任范围                              |
| ---- | ---------------------------- | -------- | ----------------------------------------- |
| S01  | 确认基线、接入契约与验收入口 | 无       | 源码清单、开发规格、交付环境              |
| S02  | 实现纯去重规划器             | S01      | Core 新增 context-folding 模块及测试      |
| S03  | 实现预算、原子投影与性能保护 | S02      | 共享策略和适配契约                        |

## 2. S01：确认开发基线与接入契约

### 工作

- 读取实际分支和相关 package-local `AGENTS.md`，核对固定 Bun、工作区状态与现有未提交修改；保持其他工作的修改不变。
- 进入实现阶段时读取 SpecGit 2 技能及本机命令契约，查重并建立完整规格 Issue，再按项目规则开展分支/PR 交付。
- 列出当前 OpenCode 和 Core runner 的普通、全文压缩、辅助请求入口，标出用途传递方式。
- 核实两个消息体系的内置工具来源、步骤边界、成功状态、指令来源、调用身份和序列化后位置。
- 明确 system/tools 的计量位置，确认最终参数修改后不会应用过期预算或映射。
- 确认外部 DCP 的准确包身份与实际加载态获取方式。
- 明确测试环境或 CLI 测试制品的部署/安装方式、回归入口及证据目录；不得猜测生产地址。
- 核对 DCP 源码来源与许可证；不把复制外部插件源码作为默认实现路径。

### 产出与完成标准

形成请求入口表、字段映射表、配置真值表、测试运行说明。将规格第 15 节的六项待确认内容逐项补齐；无法确认的结构写明跳过规则。

已支持的普通路径必须具备可测试的映射方案。不能以“所有请求都跳过”作为接入完成。

## 3. S02：实现纯去重规划器

### 改动范围

建议新增 `packages/core/src/session/context-folding/`，配套测试放入 Core 现有测试目录。优先复用现有类型和模块导出模式。

### 工作

- 定义只读候选、步骤、source/witness 引用、折叠计划及固定跳过原因类型。
- 实现工具来源白名单、成功状态、指令/附件/未知结构保护。
- 实现完整参数规范化：对象键排序，保留数组顺序、缺失/null、路径及正文差异；异常值不降级比较。
- 实现严格正文相等分组；若采用哈希，最终核对完整内容。
- 为每组固定最新完整 witness，禁止 witness 进入 source 集合。
- 实现近期完整步骤保护：至少 4 步且覆盖 16,000 个估算 tokens，保留并行兄弟工具。
- 输出按时间排序的可折叠源，不修改输入，不访问存储或模型服务。

### 验证与完成标准

覆盖 U01–U14、U18、U21，以及异常参数相关 U20。必须证明 A/B/A 保留 B 和最新 A，跨分页/工具/来源不会错误归组。

通过属性测试验证：每个 source 有后续完整 witness，witness 不被折叠，受保护内容不能进入 source。此步只产出策略，不改变产品请求。

## 4. S03：实现预算、投影与资源约束

### 工作

- 按规格第 7 节计算软预算；计入实际 system、消息、工具定义及输出预留，避免重复计算 system。
- 未知媒体、无效限额、无法确认的输出预留保守跳过。
- 超过软目标才选取 source；扣除固定占位和引用成本后，单项净收益至少 512。
- 到达目标即停止；候选耗尽仍超预算不触碰唯一内容。
- 实现转义、长度限制和唯一性检查，保证占位引用实际请求中的调用 ID。
- 实现计划校验和独立副本原子应用；中途失败返回原准备结果，无部分变更。
- 定义供两个适配层使用的映射校验契约；具体消息格式替换留给各适配层实现。
- 建立按输入字节量度量的基准，确定工作量保护上限；超限跳过，不使用近似比较。

### 验证与完成标准

覆盖 U15–U22、I11，以及共享层能够覆盖的 I04/I05/I06。测试哈希碰撞、引用失效、投影失败、共享引用污染、重复投影和净收益边界。

原始对象冻结后仍能正确运行；计划生成和副本生成均不产生持久化副作用。记录初步资源基准，不能仅断言结果 tokens 变少。

## 5. S04：配置及兼容策略解析

### 改动范围

- `packages/core/src/v1/config/config.ts`
- `packages/core/src/config/compaction.ts`
- `packages/core/src/v1/config/migrate.ts`
- `packages/opencode/src/config/config.ts`
- 实际受影响的配置测试及生成物。

### 工作

- 增加布尔字段 `compaction.dynamic`。
- 实现有效值优先级：禁用环境变量 → 显式 dynamic → 显式旧 prune → 默认 true。
- 在现有分层合并之后解析兼容，不把旧 schema 默认值误当作用户明确选择。
- 保持 `compaction.auto` 和禁用自动全文压缩环境变量独立。
- 定义外部已知 DCP 加载时退让的策略输入；真实加载态接线在 S07 完成。
- 不新增多个策略调参开关，不自动编辑用户配置。

### 验证与完成标准

覆盖 I07/I08 的全矩阵和外部 DCP 退让的纯策略用例。V1 → Core 迁移后保留显式意图。

字段声明、加载、迁移和文档默认值一致。此步不独立发布带新默认行为的产品版本。

## 6. S05：接入当前 OpenCode 请求路径

### 改动范围

主要为 `packages/opencode/src/session/prompt.ts`、`message-v2.ts`、`llm/request.ts` 及必要的内部请求类型传播；仅在需要传递内部字段时修改 processor/LLM 接口。

### 工作

- 显式传递请求用途，全文压缩/辅助/未知用途跳过。
- 在消息转换时保留内部来源映射，不能事后仅凭工具名和数组位置反推来源。
- 在实际成功结算时写入有界 session/instance 来源身份台账；只存 source/call/generation 身份，不存输入、正文、路径、指纹或计划，不持久化。重启前历史和缺失证明的调用跳过。
- 在 system/tools/params 准备完成后用共享规划器生成稳定 source/witness 计划；规划器不得内置 provider ID 规则。
- 将 `ProviderTransform.message` 的现有 Claude/Mistral ID scrub 提取为唯一共享函数，由原消息变换与折叠适配共同调用；不得复制第二份变换规则。
- AI SDK 在 provider 消息变换后、Native 在 canonical request 形成后，逐项验证最终可见 call/result ID、正文位置和唯一配对；使用最终 witness ID 生成占位并原子投影。
- 未改写 ID 或共享变换后无碰撞的 Claude/Mistral 都是正向路径；仅碰撞、未知 transformer、结构不唯一、外部执行工具等跳过。
- 投影数据只用于发送，不回流给会话存储、摘要输入或下一轮历史。
- 同一网络重试使用准备好的快照，新普通请求重新计算。

### 验证与完成标准

覆盖 I01、I03–I06、I11、I15/I16，以及存储不变、标题/摘要不参与的集成测试。分别检查 AI SDK 和 Native LLM 实际出站消息的正文、调用配对和完整 witness；Claude/Mistral 必须各有非碰撞正向用例，不能用整类 provider 跳过替代。

两种模式均经过同一策略，且禁用时恢复原请求。尚未完成 S07 前，不宣称兼容交付完成。

## 7. S06：接入 Core runner

### 改动范围

`packages/core/src/session/runner/llm.ts`、`runner/to-llm-message.ts` 及相关内部契约与测试。

### 工作

- 适配 Core 工具记录、来源、步骤和结果类型，复用 S02/S03 策略。
- 使用与 OpenCode 同一台账契约记录 application/local registration 的实际执行来源；local override、缺失记录和重启前历史均不能按工具名放行。
- 在普通请求准备完成后、现有 `compactIfNeeded` 之前应用投影；原始 entries 不变。
- 为已知内置 `read` 的 `ReadTool.TextPage` 增加正向适配：正文取 `content`；完整输入及 `type/mime/offset/truncated/next` 外层字段全部严格相等才归组。
- 仅在独立 wire JSON 副本中替换唯一 `content` 槽位，保持 result 类型、外层字段、provider 协议、持久化记录和工具输出 schema 不变；往返校验失败或 list/media/binary/未知 read 结果跳过。
- 显式隔离摘要请求，不在 Core 中复制另一套阈值或工具白名单。
- 保留已有模型切换、历史增量读取、工具结算和错误恢复语义。

### 验证与完成标准

覆盖 I02、I13/I14 以及 Core 对应的 I03–I06。执行相同语义 fixtures，核对候选选择与当前 OpenCode 一致；消息布局差异不要求序列化字节一致。

必须有 Core `TextPage` 独立正向测试和外层字段差异/未知形状负向测试，不能以 S05 的 Native LLM 或 Core grep/glob 测试替代。

## 8. S07：完成旧清理迁移、插件兼容与诊断

### 工作

- 退役当前会话退出时旧持久化 prune 的自动执行入口。
- 保留已有 `state.time.compacted` 的序列化解释，不恢复、不重新写入历史标记。
- 将 S04 的外部 DCP 兼容策略连接到准确加载态；已知外部 DCP 启用时内置退让，每实例一次迁移提示。
- 不误禁用其他插件；未知消息改写插件的兼容范围明确记录。
- 接入日志统计，未知 token 值保持未知，不记录正文、参数或指纹。
- 更新开关文案、配置迁移说明和回退说明；没有合适设置页面时不新增页面。

### 验证与完成标准

覆盖 I09/I10/I12，复跑配置矩阵和两条会话路径的关闭对照。确认默认情况下只有新请求级去噪负责清理，不再有旧持久化清理叠加。

全文压缩相关测试仍通过；`auto: false` 不禁用动态折叠，`dynamic: false` 不禁用手动全文压缩。

## 9. S08：真实宿主执行与全文压缩回归

### 工作

- 通过真实请求入口启动隔离会话，保存出站请求和原始存储前后对照。
- 使用可控 provider 构造长会话，必须观察到一次真实重复折叠，不能只断言会话完成。
- 覆盖慢工具、并行成功与失败、显式取消、自动摘要、手动全文压缩及摘要后续跑。
- 使用副作用 ledger 验证已完成工具未重放。
- 覆盖 provider 上下文拒绝、恢复成功和无法恢复的错误终态。
- 当前 OpenCode 的 AI SDK/Native LLM 与 Core runner 分别记录结果。

### 完成标准

每条路径都有：折叠命中证据、完整 witness、原始存储不变、执行结算及最终状态证据。失败状态、缺失模式和未覆盖场景如实记录，不写成通过。

本步骤证明执行和协议契约，不证明真实模型语义质量。

## 10. S09：质量、性能及缓存对照

### 工作

- 选取读取后修改、重复搜索、A/B/A 版本变化、返回先前任务等代表性任务。
- 对启用/禁用进行配对运行，固定初始工作区、模型配置及输入，保留重复运行次数与模型不确定性说明。
- 记录完成质量、遗漏约束、重复读取、工具调用、实际 tokens、缓存情况、请求准备耗时及峰值内存。
- 区分已有模拟协议证据、真实模型质量证据和实际安装制品证据。
- 复核工作量上限、错误回退和日志内容，确保去重不会成为新的资源瓶颈。

### 完成标准

所有结构与执行硬约束通过；实际发生折叠的代表性任务没有未解决的约束遗漏或执行错误。质量退步需要归因、修复或收紧策略后重测，不能用 token 节省抵消。

形成可复现对照报告。量化性能目标在基准建立后明确；不能在看到结果后任意移动门槛，也不宣称小样本证明所有模型无退步。

## 11. S10：门禁与测试版本交付

### 工作

- 核对代码、配置 schema、迁移、文档、必要生成物与测试覆盖清单。
- 执行 `bun run lint`、`bun run typecheck` 及受影响包的测试；不从根目录运行 `bun test`，不提高 lint 警告上限。
- 通过当前 PR head 的项目必需 CI；涉及 API/schema 生成或 DAG 持久化时执行相应门禁。
- 按项目 SpecGit/native forge 规则推进评审和合并，核对关联 Issue 实际状态。
- 将当前版本发布/安装到 S01 明确的测试环境，复核开启、关闭、重复折叠、全文压缩、工具连续执行及配置兼容。
- 输出版本、commit、测试地址或运行入口、关键证据、限制和关闭回退方法。

### 完成标准

测试环境运行的是验收提交对应制品，直接受影响链路验证通过，关联交付状态已核对。测试环境未定义、制品未部署或回归失败时保持未完成。

本步骤不自动授权生产发布。纯文档拆分阶段无运行产物，无需执行本步骤。
