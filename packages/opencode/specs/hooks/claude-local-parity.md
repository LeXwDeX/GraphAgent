# Claude Code hooks: local parity evidence matrix

This is an acceptance ledger for Issue #797's **local** GraphAgent hooks implementation against the Claude Code hooks reference captured on 2026-10-16 (`/private/tmp/claude-hooks-reference-2026-10-16.md`). It is not a claim that every documented Claude Code product surface exists in this fork. A source path shows an implementation; only a test that enters through the real producer, runs a handler, and observes the consumer closes an applicable event row. The acceptance target is one real producer → supported handler → consumer path for each locally applicable event, plus common handler-protocol verification; it is not the full event × handler Cartesian product. All paths below are relative to `packages/opencode/` unless prefixed otherwise. The event rows combine v1 `/session` and V2 `/api/session` evidence, with the V2 route described separately below. Evidence is scoped to the named path and execution recorded; it does not certify event×handler coverage beyond the named evidence or final acceptance beyond the gates recorded below.

The five handler columns are `C` command, `H` HTTP, `M` `mcp_tool`, `P` prompt, and `A` agent. `V` means a named test enters through the actual producer, executes that handler, and observes the consumer. `B` means a named test exercises this event and handler at the **executor boundary**, but the producer-to-consumer path for that exact pair is still unproven. `G` means the handler is enabled by `src/hook/settings.ts:supportsHandler`, but no event-by-handler observable test was found. `N/A` means this fork has no corresponding product lifecycle source, so the row is recorded as locally inapplicable rather than a missing producer. `—` means the official reference does not allow this handler on that event. A named test in the last column is evidence for a narrower producer, consumer, or executor slice; it does not silently upgrade any `B` or `G` cell to full parity.

All supported cells share the route `producer → SettingsHook.trigger` (`src/hook/settings.ts`) `→` command/HTTP/MCP/prompt/agent handler in that module `→` event-specific `TriggerResult` reduction `→` the consumer listed in the row. `src/hook/schema.ts` validates handlers/output. `src/hook/session-hooks.ts` supplies dynamic skill/agent/session registrations. A `G` or `B` cell is a transport-specific evidence limit, not by itself an Issue #797 acceptance gap when another supported handler has closed the event's real producer/consumer path. Applicable rows without any `V` still need such a test.
