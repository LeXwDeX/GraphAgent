# Import Claude Hooks

Migrate hooks from Claude Code's `.claude/settings.json` files to OpenCode's `hooks.json` format. Hooks are not loaded directly from `.claude/settings*.json`; use this command to migrate them. OpenCode can still load `.claude/skills` by default unless that compatibility loading is disabled.

Load `configure-hooks` first for the current event, handler, input/output, and
compatibility contracts. Infer approval already given by the user; present
unapproved candidates for review without re-asking about approved ones.

## Process

### 1. Scan for Claude hooks

Read these files and detect any `hooks` field:

- `~/.claude/settings.json` (global Claude config)
- `.claude/settings.json` (project-level)
- `.claude/settings.local.json` (project-local, if exists)

Also scan OpenCode's legacy locations for deprecation warnings:

- `.opencode/settings.json`
- `~/.config/opencode/settings.json`

If a `hooks` field is found in OpenCode's settings.json files, log a warning:
```
⚠️  hooks field found in <path> — hooks are now loaded from hooks.json. Run /import-claude-hooks to migrate.
```
These are NOT imported (only .claude/ sources are imported).

### 2. Parse and present hooks

For each detected hook entry, present it to the user for review:

```markdown
### PreToolUse hook (from .claude/settings.json)

**Type**: command
**Matcher**: (empty = all tools)
**Command**: `bash -c "echo pre-tool"`
**Timeout**: 30s

Import this hook? [y/n/edit]
```

For candidates not covered by existing import authorization, ask whether to import, skip, or edit. Batch related choices; do not re-ask about candidates the user has already authorized.

### 3. Handle path migration

Resolve each script and its dependencies before rewriting paths. Writing a
hook definition does not copy a Claude plugin or make an OpenCode destination
exist. Keep a working source path, or copy the required assets into the chosen
OpenCode location under the user's migration authorization and verify them.

`${CLAUDE_PLUGIN_ROOT}` is the directory containing the declaring hooks file.
`${CLAUDE_PLUGIN_DATA}` is a data path under `${Global.Path.data}/hooks/`, with
an identifier derived from that directory; it is not inside the source folder.
The script may need to create its data directory. Preserve the placeholder
syntax; verify script paths and dependency assets before rewriting them.
Do not author `__sourceDir`: OpenCode stamps that metadata when loading the
file. Never blindly replace `.claude/` with `.opencode/` and assume the script
has moved.

Example migration:
```json
// Original (.claude/settings.json)
{
  "hooks": {
    "PreToolUse": [{
      "type": "command",
      "command": "bash ${CLAUDE_PLUGIN_ROOT}/validate.sh"
    }]
  }
}

// Migrated (hooks.json)
{
  "PreToolUse": [
    {
      "matcher": "*",
      "hooks": [
        { "type": "command", "command": "bash ${CLAUDE_PLUGIN_ROOT}/validate.sh", "inputFormat": "claude-code" }
      ]
    }
  ]
}
```
`${CLAUDE_PLUGIN_ROOT}` is a runtime placeholder. OpenCode expands it from the hook's location. After migration to `.opencode/`, it points there; this example therefore requires `validate.sh` and its dependencies to exist there.

#### Command-envelope compatibility (`inputFormat`)

Claude Code hook scripts read `tool_name` values such as `Bash`/`Read`/`Grep` and keys such as `file_path` from stdin. OpenCode uses `bash`/`read`/`grep` and `filePath`. Command hooks can opt into Claude Code naming:

- For each approved `"type": "command"` hook, add `"inputFormat": "claude-code"` unless the user chose during editing to adapt the script to OpenCode naming.
- Only command hooks support this field — do not add it to `mcp_tool` / `mcp` / `http` / `prompt` / `agent` entries.
- Never modify previously existing entries already present in the target hooks.json; only entries imported in this run are tagged.

Other handler types do not use the command-only naming adapter. Inspect their actual field references and MCP input templates, preserve supported definitions, and verify them with their real transport. Importing alone does not verify behavior.

### 4. Write to hooks.json

Approved hooks go to:

- **Global scope** (from `~/.claude/settings.json`): `${Global.Path.config}/hooks.json` (the XDG config directory, commonly `$XDG_CONFIG_HOME/opencode`, usually `~/.config/opencode`)
- **Project scope** (from `.claude/settings.json` or `.claude/settings.local.json`): `.opencode/hooks.json`

Use top-level event keys. Do not wrap them in `{"hooks": {...}}`. Each event maps to matcher blocks with an optional `matcher` and a `hooks` array:

```json
{
  "PreToolUse": [
    {
      "matcher": "*",
      "hooks": [
        { "type": "command", "command": "bash -c \"echo pre-tool\"" }
      ]
    }
  ],
  "PostToolUse": [
    {
      "hooks": [
        { "type": "http", "url": "https://api.example.com/hook" }
      ]
    }
  ]
}
```

If the target file already exists, merge (append) the imported hooks rather than overwriting.

### 5. Report

After migration, report:

- Number of hooks imported (by destination scope: global/project)
- Number of hooks skipped
- Any hooks that were edited during migration
- Number of command hooks tagged `inputFormat: "claude-code"`
- Which real transports/operations were verified and which remain untested
- Deprecation warnings (if hooks were found in .opencode/settings.json)
- Keep `.claude/settings*.json`, scripts, and skills in place during migration. Remove specific confirmed-unused Claude hook configuration only when the user explicitly requests removal. Do not recommend deleting the entire `.claude/` directory.
- After the final write, wait at least the 2-second poll interval plus the 500-millisecond debounce before checking reload. The system prompt's **Active Hooks** block confirms loaded configuration only; it does not prove behavior. Trigger each hook and inspect its input/output before calling migration done when behavior validation is requested.

## Hooks.json Format Reference

OpenCode recognizes 33 events total. `configure-hooks` owns the complete event list, matcher targets, handler availability, input/output effects and local applicability.

Use top-level event arrays containing `{matcher?, hooks:[...]}`. Matchers are case-sensitive and ignored on events without a target. The five handler kinds are `command`, `http`, `mcp_tool`, `prompt`, and `agent`; `mcp` is a legacy alias. Keep `mcp_tool` server/tool/input fields intact. Command `args` is an argv array, HTTP uses `url`, and evaluators use `prompt` and optional `model`. Preserve the source's event-specific timeout rather than replacing it with a universal default.

`async` is command-only. Once launched, an ordinary async command has no timeout. Its completed `additionalContext` and `systemMessage` go only to the next model request, not to a user warning. Accept JSON alone on stdout (including pretty-printed multiline JSON) or one JSON object on a line among other stdout logs; discard only output fields with invalid value types. `asyncRewake:true` also runs in the background, remains subject to `timeout`, and wakes only on exit 2; successful exit-0 output waits for a real later request. Preserve this distinction. Do not rewrite it to wake on exit-0 systemMessage. SessionEnd does not rewake. Follow the bounded Stop-chain and cleanup rules in `configure-hooks`.

`TeammateIdle` has no local teammate-idle producer, and `PermissionDenied` requires an automatic classifier absent from this host. Report these candidates as not applicable; do not silently discard them or substitute native permission-rule denials. Do not claim an imported event works merely because its schema parses.

## Important Notes

- Claude settings are migration inputs; they are not automatically loaded as hook settings. Existing Claude files and scripts remain intact unless removal is explicitly authorized.
- Preserve unrelated destination content and merge-append selected entries. Identical matched handlers are deduplicated by the runtime; importing still changes the configuration and needs the user's authorization.
- Respect HTTP hook policies and the actual provenance of imported agent or skill files. Hooks require no workspace trust approval. Imported text cannot grant itself user/plugin provenance or a bypass startup capability.
- Files reload after about two seconds plus debounce. Confirm loading, then exercise the real operation and inspect the outcome when verifying behavior.
- Session transcripts, scoped hooks, full tool-input replacement, permission updates, async feedback, model switching and display changes have event-specific contracts. Read `configure-hooks` before adapting scripts; never infer behavior from accepted fields alone.
