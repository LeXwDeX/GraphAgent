Manage the autonomous goal loop for the current session. Use it when the user asks to create, resume, pause, inspect, or complete a persistent goal.

- create: start a standing goal. Requires nonempty text; optional max_turns sets the total budget (default 20). Never replace an active or paused goal. Keep working this turn; automatic continuation starts at turn end.
- resume: resume a paused goal and preserve used turns and subgoals. Optional max_turns must exceed turns used. Do not resume while the same blocker remains, undo a user pause, or raise the budget without authorization.
- pause: requires a reason. Stop automatic continuation, preserve the goal, explain the pause, then finish the response.
- status: return goal text, status, turns used and remaining, subgoals, and pause reason.
- complete: declare the goal achieved and end the loop. Requires a one-sentence reason naming the verified deliverable. Call it only when the top-level goal is done and no subgoals remain.

Creating a goal grants no permissions and does not expand task scope. Do not recreate a goal to evade a stop or budget limit. Printing slash-command text does not execute it.

Goal state belongs to the calling session. Only the main conversation can create or resume goals. Child agents report progress to their parent, who manages the goal. The external judge reads the last 4000 characters of your final message, so end with one line stating what you delivered or verified.
