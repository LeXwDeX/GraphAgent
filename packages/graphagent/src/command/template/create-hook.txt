# Create Hook

Load `configure-hooks` first. Infer the event, action, destination and write authorization already supplied. Ask only for missing choices that affect behavior.

## Select the event and handler

Use the event list in `configure-hooks` to recognize supported events. Check local applicability before writing:

- Tool: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`
- Permission: `PermissionRequest`
- Session: `Setup`, `SessionStart`, `SessionEnd`, `Stop`, `StopFailure`
- Subagent: `SubagentStart`, `SubagentStop`
- Prompt and compaction: `UserPromptSubmit`, `UserPromptExpansion`, `PreCompact`, `PostCompact`
- Task: `TaskCreated`, `TaskCompleted`
- MCP: `Elicitation`, `ElicitationResult`
- Environment: `Notification`, `ConfigChange`, `WorktreeCreate`, `WorktreeRemove`, `InstructionsLoaded`, `CwdChanged`, `DirectoryAdded`, `FileChanged`
- Model and display: `PreModelSwitch`, `PostModelSwitch`, `MessageDisplay`

Reject unknown event names; explain that they are unsupported rather than inventing a producer.

Use the handler types and per-event restrictions in `configure-hooks`:

- `command`: command and optional argv `args`; `shell` applies to shell execution.
- `http`: `url`, optional headers and environment allowlist.
- `mcp_tool`: `server`, `tool`, and optional templated `input`.
- `prompt` or `agent`: `prompt`, optional model; evaluator output is `{ok,reason?,impossible?}`.

Matchers are case-sensitive. Use the event's documented target, such as `Bash`, source, agent type, server name, command name, error category or canonical model name. Omit matchers on events without a target. Conditions are filters and grant no permissions.

Set a finite `timeout` (seconds) appropriate to the operation. Defaults: foreground command, HTTP and MCP hooks 30 s; `Stop`, `SubagentStop`, `TaskCompleted`, `PreCompact` and `PostCompact` 60 s; background `async`/`asyncRewake` commands 600 s; `prompt` 30 s; `agent` 60 s; `UserPromptSubmit`, `PreModelSwitch` and `PostModelSwitch` 30 s; `SessionEnd` 1.5 s. An explicit `timeout` always overrides. `statusMessage` is visible progress. `once` is scoped to supported skill/session registrations. Command `async:true` has no timeout after the background process starts; its `additionalContext` and `systemMessage` are delivered to the next model request, not shown as user warnings. Print JSON alone on stdout (pretty-printed JSON may span lines), or as one JSON line among other stdout logs; fields with invalid value types are dropped independently. `asyncRewake:true` also runs in the background but remains subject to `timeout` and wakes only on exit 2; exit-0 output waits for a real later request. Stop scripts must honor `stop_hook_active` and be idempotent.

## Choose and write the file

- Global: `${Global.Path.config}/hooks.json`, following XDG configuration.
- Project: `${PROJECT_DIR}/.agents/hooks.json`.
- Project-local: `${PROJECT_DIR}/.agents/hooks.local.json` for private hooks that must not be committed. While Git does not track the file it is user configuration; a tracked copy counts as a project file.

Read the destination first. Append the intended matcher block to its event array, preserving every sibling event and unrelated field. Create missing directories/files only within the chosen scope. Do not overwrite the whole existing configuration or delete unrelated hooks. Hooks in the project `hooks.json`, or in a `hooks.local.json` that Git tracks, require the user's confirmation through `/trust` before they execute; global hooks and hooks in an untracked `hooks.local.json` are user configuration and need no confirmation. Preserve tool permissions, HTTP hook policies, and the actual source of scoped hooks; a repository cannot grant itself a bypass startup capability.

```json
{
  "PreToolUse": [{
    "matcher": "Bash",
    "hooks": [{ "type": "command", "command": "./scripts/check.sh", "timeout": 10 }]
  }]
}
```

Show the exact addition and destination before an unapproved write. If the user already requested creating and writing that hook, proceed under that authorization. Repair invalid JSON introduced by your write and reread it; preserve pre-existing corruption if a safe merge cannot be determined.

## Verify

After the final write, allow the two-second poll interval plus debounce. Inspect Active Hooks or the session registration API to confirm loading. Then trigger the intended operation with a controlled fixture and check both handler input and its observable consumer. A loaded configuration alone does not establish execution or compatibility. Report the destination, event, behavior tested and any applicable local limit.
