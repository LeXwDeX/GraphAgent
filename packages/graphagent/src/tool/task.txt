Delegate a self-contained task to a subagent.

{{delegation_criteria}}

- Specify subagent_type from the available agent types. Respect inherited permissions; each run has its own `maxToolCalls` budget.
- Give each agent all needed context: a new agent starts fresh and does not see this conversation. State whether it should write code or research, and include verification steps.
- Launch independent agents concurrently in one message. Do not repeat a delegated task; wait or continue other work.
- The agent returns one message that the user cannot see; summarize it. Check key claims, such as changed files or test results, before relying on or reporting them.
- Pass action="resume" with task_id to continue a previous task with its history.

Choosing foreground or background:
- When the user says they will keep working on something else while this is done ("meanwhile",
  "at the same time", "I'll keep working on ...", "no need to wait"), or asks for background, do
  not do that work yourself in this turn: delegate it with background:true, provided the agent only
  reads, or writes files neither you nor the user will touch, and its result fits in one message.
  Delegate first: do not read files or run commands to investigate that work beforehand; pass on
  the user's request and what you already know, and the agent gathers its own context. Then carry
  on with any foreground work the user also asked for; if none is left, reply briefly and end your
  turn. The result arrives as a message.
- Otherwise use foreground (the default). Always foreground when: you need the result for your next
  step; the work needs the user's input or confirmation; it changes shared session state; or it is
  a quick lookup you can answer directly.
- Reviews, audits, and test or type-check runs of finished work are good background tasks. Research
  that decides your next edit is not.
- Never run two writers on the same files. Never background a task and then wait for it with
  sleep or polling; if nothing else is left, end your turn and the result will arrive as a message.
- A declared execution mode of an agent or command takes precedence over these criteria: pass
  background=false to wait for an agent that runs in the background by default. Interactive agents
  always run in the foreground and refuse background=true.
