# Nix toolchain verification

The flake reads exact Bun, Node and Go pins from the repository through
`toolchain.nix`. Evaluation rejects different patch versions, and native shell
and package builds check the installed executables. The desktop package uses
its own exact Electron pin from `packages/desktop/package.json`; its embedded
Node runtime is independent of the development Node pin.

Desktop builds use the same `bun run build` entrypoint locally, in CI and in
Nix. Its wrapper checks the repository's exact Bun and Node pins, resolves
electron-vite from the installed package and gives
the build's Node process a 4096 MiB old-space budget, preserving other caller
`NODE_OPTIONS` flags. This budget covers Rollup parsing the bundled backend;
it does not change the packaged Electron application's runtime heap.

The reviewed [`nixpkgs-unstable` input](https://github.com/NixOS/nixpkgs/tree/c9fe7d12cd78d1adcd12dd15e24432dde5b155a0)
provides Bun 1.4.2, Node 24.21.0 and Go 1.27.1. Nixpkgs 26.11 removed Intel
macOS support. Only `x86_64-darwin` therefore selects the official
[26.05 Darwin input](https://github.com/NixOS/nixpkgs/tree/68e5b9f7e82a76a5171d10b5d316e0ae5e1df6e9),
which supplies the same Node and Go pins and receives upstream support through 2026. That platform calls the current official Bun recipe with the legacy
Darwin toolchain and the upstream Intel baseline archive. This is specific to
Nix packaging; it does not change the ordinary CLI installer platform contract.

The conventional `nixpkgs` input follows `nixpkgs-darwin` so that `nix develop`
can resolve its own modern Bash on every platform. The [Nix 2.35 shell resolver](https://github.com/NixOS/nix/blob/2.35.0/src/nix/develop.cc#L591-L626) selects
`bashInteractive` from that conventional input before loading the shell
environment. Selecting unsupported unstable Intel Darwin there makes Nix
fall back to the host Bash 3.2, which cannot parse the stdenv's `;&` case syntax.
Package selection continues to use `nixpkgs-unstable` except for Intel Darwin;
the supported Bash input does not change the exact Bun, Node or Go checks.

`flake.lock` was generated by a real Nix 2.35.0 evaluator. On this development
host, the official SHA256-verified Darwin Nix archive was relocated entirely
under a private temporary directory for evaluation; no global `/nix` store or
Nix daemon was installed. CLI, desktop, updater and shell derivations evaluated
for all four platforms, including exact Bun/Node/Go versions in each shell.
The conventional Bash input also evaluates to Bash 5.3p9 on all four platforms.
Relocated evaluation does not certify native builds.

Electron is packaged from official 42.11.9 archives. All four archive streams
were hashed and checked against the upstream release's `SHASUMS256.txt` and
GitHub asset digest. `electron-sources.json` records those flat archive hashes;
Linux retains nixpkgs' binary library and interpreter patching, and Darwin uses
the upstream application bundle. The Intel Bun archive was independently
checked against its upstream release asset digest. None of these flat source
hashes substitutes for the workspace dependency output hash.

The required desktop ripgrep archive is also a fixed `fetchurl` source,
verified against downloaded bytes and its official release digest. Before the
ordinary desktop prebuild, the existing RuntimeAsset helper primes its cache
from those bytes, retaining its archive and executable receipt checks. This
keeps the required prebuild hooks enabled without fetching inside a normal
Nix build sandbox. An isolated local cache was verified with public fallback
and network fetches disabled.

The committed workspace hashes and both normal CLI and desktop derivations
passed native verification for all four platforms at commit
`67ce58b7badea7d0a4dab7106c6c6699041e46ef` in
[workflow run 37085826496](https://github.com/LeXwDeX/OpenCode-GraphAgent/actions/runs/37085826496).
This historical result does not certify later source or dependency changes.
Each affected revision still requires its own native measurements and builds.

Nix outputs are development builds (`0.0.0-dev.<revision>` and channel `dev`).
They do not derive a product release version from the opencode package version.
Stable GraphAgent versions come only from `graphagent-v*` tags through the
existing `.azure-pipelines/release.yml` build path.

## Native acceptance

The Nix verification workflow uses isolated GitHub-hosted runners for both
Linux architectures and both Darwin architectures. It checks native platform
identity and exact installed runtimes, then builds the fake-hash updater.
Only a hash mismatch for that exact updater derivation yields a candidate;
dependency downloads, installation failures and other mismatches fail without
inventing a hash. Each job preserves logs, the lock, the measured candidate
hashes and source commit in an artifact.

A normal PR run rejects stale committed hashes. Review each platform's
measurement artifact, copy only its `nodeModules.<system>` value into
`hashes.json`, and run the workflow again to build the normal packages.
A manual run with `regenerate_hashes: true` applies only the measured native
hash in the ephemeral runner before those acceptance builds. It never pushes
or commits the result. All four successful native builds are still required
before claiming four-platform Nix package support.

The equivalent local commands on a native Nix host are:

```sh
python3 nix/scripts/verify_build.py --system "$(nix eval --impure --raw --expr builtins.currentSystem)"
# To measure and apply the native candidate before both package builds:
python3 nix/scripts/verify_build.py --system "$(nix eval --impure --raw --expr builtins.currentSystem)" --apply
```

The measured hash parser's rejection tests run with:

```sh
python3 nix/scripts/test_verify_build.py
```
